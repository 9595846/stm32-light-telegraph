# 阶段 2：烧录与实物验收

## 接好后先做什么

1. 断电对照 `接线图.png` 和 `01_接线.md`。现有 GPIO 接法不变；舵机先不供电，本固件不会启动 PWM。
2. 将 LED1 的发光面朝向光敏元件，先从很近的位置试。用不透光纸筒挡住杂光，但不要挡住 LED1。把 LED2、模块上的指示灯和 OLED 的光挡在光路外。
3. 光敏 VCC 必须沿用 3.3V，AO 接 PA1，DO 留空。LED1 为 PA0 → 1kΩ → 阳极，阴极接 GND。
4. 初次不安装舵机遮光片。独立 5V 与 STM32 3.3V 不相连；如果接上舵机电源，负极必须与 STM32 共地。

## 编译与下载

1. 用 Keil 打开本项目的 `../firmware/Project.uvprojx`，选择唯一目标 `Light_Telegraph`。不要打开旧的 `Defuse_Base` 或其他项目。
2. 继续使用 ARM Compiler 5。本次实际使用 V5.06 update 7 build 960，主频配置沿用 HSI/PLL 64MHz，STM32F103C8 / 64KB Flash / 20KB RAM。
3. Rebuild，确认 0 Error、0 Warning。下载器沿用 ST-Link / SWD，经专用 SWD 接口下载，随后复位。
4. OLED 应显示“光影电报机”和“请先按1标定”。串口启动行应是 `LIGHT TELEGRAPH STAGE2 V1.0 READY`。若仍显示旧项目，先检查下载目标和复位，不改接线凑结果。

本次实际编译产物：`../firmware/Objects/Light_Telegraph/Light_Telegraph.axf`，以及 `../firmware/release/Light_Telegraph.hex`。Keil 可用 AXF 下载，不需要另外复制旧 HEX。

可复现命令（在 `firmware` 目录）：

## 四个按钮与旋钮

| 操作 | 当前实际功能 |
|---|---|
| KEY1 / PB12 | 开始或重新开始明暗标定；先停发送 |
| KEY2 / PB15 | 停止标定/发送/手动亮灯，熄灭 LED1；同时按多键时优先停止 |
| KEY3 / PB8 | 标定有效时发送固定 SOS |
| KEY4 / PB9 | 首页 → 光敏数据 → IMU 诊断 → 首页 |
| 转动编码器 | 空闲时每格调整 50ms，范围 300～1000ms；发送或标定时忽略 |

这一阶段尚未实现文字编辑。旋钮调整的是每个短闪的时长，不是角度；数字越大，发送越慢。转动方向和每格计数仍需实物确认。

## 按顺序验证

### 1. 手动明暗

Tera Term 设为 115200、8位数据、无校验、1停止位、无流控。

发送 `LAMP OFF`，约 1 秒后发送 `STATUS`，记录 RAW。发送 `LAMP ON`，约 1 秒后再发 `STATUS`。来回至少 5 次，看 RAW 是否跟着灯开关重复变化。

手动亮灯时暂停接收，不把手动操作记录成消息。结束发送 `LAMP OFF`。AO 有数字不是模块已连接的证明，必须观察与灯光的对应变化。

### 2. 自动标定

保持光路畅通，按 KEY1，或发送 `CAL`。程序依次进行：

- 熄灯稳定约 0.6 秒，采集暗态约 1 秒。
- 亮灯稳定约 0.6 秒，采集亮态约 1 秒。
- 再熄灯稳定约 0.6 秒。

总计约 3.8 秒。成功后首页显示“就绪”，`STATUS` 中 `CAL=1`、`ERROR=OK`，LED2 亮。

程序从采集结果判断亮态数值较大还是较小，不预设 AO 极性。当前保守启动条件是均值差至少 16 个 ADC 计数，且大于两段采样中较大波动范围的 4 倍；这是可调整的软件条件，不是已验证的传感器参数。单段至少需要 50 个有效采样。

`LOW CONTRAST` 表示明暗差异不足或波动过大：先检查是否指向真正的光敏元件、缩短距离、遮挡杂光，或核对 LED 电阻，再重新标定。不要直接把失败当成需要降低阈值。

### 3. 发送 SOS

默认短闪 300ms，长闪为其 3 倍。按 KEY3 或发送 `SEND SOS`，先有 7 个码元的暗间隔，随后 LED1 发出三短、三长、三短。包含末尾留白，默认约 12.3 秒完成。

看串口逐次出现接收文字，最后 `RX=SOS `（尾随空格是单词间隔）。OLED 首页应显示 `RX:SOS`。`TX ENDED` 只表示发送结束，不能代替接收成功。

如果接收遗漏或乱码，先用 `UNIT 500` 或 `UNIT 1000` 放慢，然后重新发送；若环境光变化，应重新 `CAL`。代码支持接收 A～Z 和 0～9 的摩斯码，首版发射只提供固定 SOS。

### 4. 检查确实经过了光路

重新发送前，保持现有标定，把不透光纸片放在 LED1 与探头之间，全程挡光，再按 KEY3。每次开始发送都会清空接收窗口，正常情况下不会再次得到 SOS。

如果仍能完整收到，检查纸片漏光、反射光或没有真正挡住探头。程序不会从发送队列复制 SOS 到接收窗口。全程断光不一定触发错误，因为接收端可能把它视为没有收到任何信号。

移开纸片，重新标定再发，确认能恢复。暂不让舵机自动挡光。

### 5. 停止与其他输入

- 标定、亮灯和发送过程中按 KEY2，LED1 应熄灭；标定中途停止后，必须重新标定。
- 发送中转旋钮，码元时长不应变化；结束后旋钮可调整速度。
- 按 KEY4 应切换三个页面，不应意外点亮 LED1 或启动舵机。

## 串口命令

```text
HELP
STATUS
LAMP ON
LAMP OFF
CAL
UNIT 300
UNIT 500
UNIT 1000
SEND SOS
STOP
```

命令不区分英文字母大小写。`UNIT` 只接受 300～1000 的十进制整数，且要求空闲；不能附加尾巴。CR 或 CRLF 均可。超长行、非 ASCII 字符和串口接收溢出会丢弃到下一个换行；先单独回车，再重发短命令。

`STATUS` 的 RAW 为最近一次采样，DARK/BRIGHT 为上次采集均值，LOW/HIGH 为迟滞阈值。是否能用看 CAL；失败或重启后不能只看保留数值。ADC 超过 100ms 没有有效更新会报告 `NO ADC`、停止发射并撤销标定；这不能识别所有断线，悬空 AO 仍可能有转换值。发送切换晚于计划超过码元时长的三分之一时，报告 `TIMING` 并停止。

IMU 仅保留诊断功能，为避免总线耗时干扰光学采样，标定或标定有效时暂停 IMU 更新；旧值不当作实时姿态。串口 MPU/MPU_AGE 可观察其是否新鲜。
